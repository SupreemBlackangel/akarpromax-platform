# Known Technical Debt Register — Staging Release Candidate 1

Accepted, non-blocking technical debt for `staging-rc1`. These are NOT launch
blockers. Active launch/external blockers are tracked in
`FINAL_GAP_REGISTER.md` (Open section) and `STAGING_READINESS.md`.

| ID | Area | Description | Impact | Why accepted | Owner / Action |
|---|---|---|---|---|---|
| TD-01 | Services identity | Legacy email-keyed participant/ownership references in the services DB; `rekeyServiceUserReferences` (`lib/services/identity.ts`) updates ~20 tables without a wrapping transaction (caller compensates only if the auth `users.email` write fails). | Rare mid-rekey interruption could leave split references across old/new email keys. | Small window, migration-time concern, single-user action; transactional split would be a larger services-DB refactor. | Tech lead — wrap rekey in a transaction when services persistence is migrated to UUID keys. |
| TD-02 | Dev dependency chain | `ws@8.18.0` (16 high findings via `npm audit`) reachable only through dev tooling `@cloudflare/vite-plugin@1.37.1` → `miniflare`. `npm ls --omit=dev ws` is empty; NOT in the production runtime tree. | None at runtime; build/dev-only exposure. | Fix requires upgrading `@cloudflare/vite-plugin` outside its stated range (1.51.1, breaking). No-version-churn policy unless it becomes a real blocker. | Dev-ops — revisit at the next planned toolchain upgrade. |
| TD-03 | Email | Real SMTP provider + SPF/DKIM/DMARC not configured; transport is `console`, `productionCapable=false`. | Blocks inbox delivery certification / UAT email journeys. | External configuration requiring PO + infra + DNS approval; not a code defect. | PO + infra — configure provider, DNS, then certify inbox. |
| TD-04 | Legal | All legal center documents carry `REQUIRES HUMAN LEGAL REVIEW BEFORE PRODUCTION`. | Content must not be presented as final legal terms. | Professional legal review is out of engineering scope. | Legal counsel — review before production go-live. |
| TD-05 | Docs | `SERVICE_PROVIDERS_APPLY` permission is documented in `docs/services/*` RBAC pages but the provider apply route enforces ownership + profile existence instead of that permission (gate removed because profile creation is already self-serve and apply is owner-only). | Doc/code wording mismatch only; no authorization regression. | Removing the gate aligns apply with the un-gated own-profile upsert; re-adding it would break the self-serve flow. | Tech lead — update `SERVICES_RBAC_POLICY.md` / `PROVIDER_VERIFICATION_POLICY.md` wording. |
| TD-06 | Content | `/providers` page and the Providers tab of `/directory` render near-identical provider listings. | Mild content duplication in public nav. | Both are routed entry points; no functional defect. | Product — decide canonical surface before production SEO pass. |
| TD-07 | Lint | 63 pre-existing ESLint warnings (unused vars, `exhaustive-deps`, `no-img-element`, …). Zero errors. | Cosmetic / future-bug risk only. | Out of scope for a freeze; no feature work allowed. | Tech lead — clean incrementally post-freeze. |
| TD-08 | Live-PG test | `tests/amrs/pg-identity-schema.test.ts` runs real DDL when `DATABASE_URL` is set (temp schema, dropped; `CREATE EXTENSION pgcrypto` persists at server scope) and self-skips when unset. | Only ever point it at a disposable dev/staging database; never production. | Needed for clean/upgrade certification evidence. | Tech lead — add an explicit `TEST_DATABASE_URL` guard / skip policy for CI. |
| TD-09 | SEO infra | No `robots.txt` / `sitemap.xml`; admin/account/workspace areas are not explicitly `noindex`ed; canonical link tags are not emitted (only environment-aware `metadataBase`). | Crawler guidance and canonical dedup only; private data is behind auth. | Production SEO artifact; staging noindex is an infra (deployment) concern. | Tech lead — add robots/sitemap/noindex before production go-live. |
| TD-10 | Routing | No public `/properties` index (only `/properties/[id]`) and no `/account` index (only `/account/security`). | None — matches the actual route set; not a defect. | Scope decision; property listings are reached via services/catalog and direct links. | Product — revisit when a property marketplace is built. |
